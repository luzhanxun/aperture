UI Guide · v1.1

一套克制的界面语言

所有界面共用一套 token：一个强调色、七组语义色相、四级文字、一套间距。v1.1 在不改变「蓝色只表可交互」的前提下补入了色彩与影像，让界面在客户面前有温度；v1.1 同时把十二屏收进同一个原型：十一屏共用外壳，客户链接页独立成页。

颜色

  • 主文字与画布的对比度 ≥ 7:1，次级文字 ≥ 4.5:1。
  • 不在强调色上再叠加浅色文字，强调色按钮统一用白字。
  • 文字形式的链接按底色分两档：浅底用 --color-accent-strong，深色英雄区用 --color-accent-text，两者在各自底色上都 ≥ 4.5:1。
  • 状态用文字 + 6px 圆点表达：正常为绿，进行中为琥珀，临期为橙，失败为玫红，AI 处理为紫，关闭为灰。

01b · Color extension

色相：只表意，不表交互

v1.0 的克制是对的，但全灰的画面无法让人在十秒内分辨「这是哪类素材、这条数据在说什么」。v1.1 补入七组色相，只允许出现在三处：影像与插画、数据可视化、内容分类与状态。蓝色仍是唯一的交互信号，任何一个色相都不得用来画按钮描边或可点击文字，否则客户会误判哪里能点。

  • 一个色相只背一个含义，跨页面复用，不按页面重新分配。
  • 色相不进入文字层级：正文永远是四级中性色，颜色只出现在圆点、标签底、图形与图表。
  • 同一屏内不出现三种以上色相，避免变成彩色货架。

05 · Motion

动效与反馈

动效只用于解释状态变化，不用于装饰。所有过渡 120–200ms，统一缓动曲线。

  • 抽屉从右侧滑入 200ms，遮罩同步淡入；关闭后焦点回到触发按钮。
  • 批量操作条从底部升起 200ms，选中数量变化即时刷新。
  • 悬停只改变文字颜色或背景，不做缩放与旋转。
  • 系统开启「减少动态效果」时，所有过渡降为 0.01ms。

06 · Accessibility

可访问性与响应式

  • 所有可交互元素可用键盘到达，焦点环 2px 强调色，不做 outline: none。
  • 对比度：主文字 15.4:1、次级文字 6.7:1、辅助文字 4.6:1（画布上均 ≥ 4.5:1，AA 达标）。
  • 强调蓝在画布上为 4.3:1，按规范只用于可交互文本与选中态，不用于正文段落。
  • 点击区域不小于 44×44px；图标按钮必须有中文 aria-label。
  • 图片有 alt：装饰性为空，内容性描述画面与地点。
  • 表格使用 th scope，展开行同步 aria-expanded。
  • 900px 以下后台侧栏折为顶部横条，640px 以下全部单列。
  • 320px 宽度下不出现横向滚动；表格可横向滚动但页面不滚动。

07 · Avoid

禁用清单

  • 不用阴影制造层级，只有抽屉、浮层与提示条例外。
  • 不用彩色渐变、玻璃拟态卡片或装饰性插画。
  • 不用 emoji、图标或插画填充空状态。
  • 不给卡片、按钮、输入框、筛选标签加边框。
  • 不用彩色胶囊表示状态，改用文字加圆点。
  • 不把强调色用于装饰、标题或大面积背景。
  • 不使用纯黑 #000 作为文字颜色。
  • 不在同一屏堆叠超过三级字号与两种强调色。

08 · Shell & Routing

一个外壳，十二个视图

前版把每屏做成独立 HTML，客户需要在十一个标签页之间来回点，看到的是十一个碎片。v1.1 收成一个单页应用：顶部外壳固定不动，只有下面的内容区在换。任何一个视图都能直接分享，浏览器前进后退照常可用，刷新不会丢失位置。客户打开销售链接的 #/link 是唯一例外：它模拟客户在微信里点开的那一页，不使用内部导航。

地址 视图 客户用它确认什么
#/overview总览系统边界与八个子系统的关系
#/library素材库检索、筛选、详情抽屉、批量操作
#/upload上传与元数据治理批量入库、AI 预填、审核队列
#/sales销售链接链接配置、有效期、访问上限与成交
#/buy客户端客户看到的素材商店、价格与授权范围
#/link客户销售链接页客户点开链接后的预览、授权与支付（无内部导航）
#/stats数据看板指标口径与漏斗
#/admin后台账号、角色、权限矩阵、审计日志
#/login登录身份与安全策略
#/agentAI智能体整合工具在真实对话里怎么被调用
#/mcp智能体接口规范对外暴露的五个工具与字段
#/design设计规范本页：数值与规则
  • 切屏时内容区做 10px 上移淡入，250ms；开启「减少动态效果」时不播放。
  • 当前所在的导航项使用深色底 + aria-current="page"，颜色不参与标识。
  • 锚点链接写成 #/admin 加 data-goto，例如把「权限矩阵」这一条直接发给客户，打开就停在矩阵那一屏。
  • 总览使用深色英雄区，进入总览以外的任意视图时外壳自动回到浅色，不出现两套导航。
  • #/link 不显示外壳导航与登录态，只保留右上角「返回原型 · 销售链接」作为唯一出口；客户不会用内部导航找到它。
  • 上传与元数据治理不占顶部导航，入口放在后台管理的侧栏；#/upload 仍可直接访问与分享。
  • 客户页与销售链接必须共用同一组事实：链接编号 SL-260418-07、有效期 2026-04-25、访问 12 / 50、素材 DM-20260412-0031，漏斗仍是 1,284 / 986 / 512 / 176。

09 · Agent demo

AI智能体整合：在真实界面上演两遍

接口规范只能回答「有哪些工具」，回答不了「它能帮我干什么」。所以 #/agent 用一张真实的对话产品截图作底，把光圈AI 的工具调用叠在对话里，用播放器把完整任务从提问走到交付。客户看到的不是示意图，而是工具在一次真实对话中的位置。两个场景对应需求书 5.2 的两条验收基准：运营岗的素材任务、管理岗的上传统计。

B · 管理决策管理岗：统计 2026 Q3 上传情况，并按素材所有者分类aggregate_uploads → list_collections → export_to_excel

  • 两个场景共用同一底板与播放器：切换场景即切工具链，不新开页面，不换视觉语言。
  • 每一步停留时，说明必须回答「这一步客户得到了什么」，而不是复述工具名。
  • 底图属于客户提供的真实产品，只作演示背景，不修改、不冒充光圈AI 的界面。
  • 两段演示同时录成 .webm（1280 × 800，无声循环）与 .gif（640 × 400），放在 assets/media/，可直接进汇报与微信。
  • 演示上方是「接入原理」三层卡（能力 MCP → 编排 Skill → 接入 Plugin），只解释各层管什么、配一个例子，不展开协议细节；工具清单与参数以 #/mcp 为准，两处工具名必须一致。
