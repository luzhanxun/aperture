接入原理

三层，让智能体「能调、会调、装得上」

光圈AI 不做自己的聊天窗口，而是把系统能力按 MCP 标准开放出去，用 Agent Skill 把高频任务编排好，再以 Agent Plugin 的形式装进智能体。客户不需要理解协议细节，只需要知道这三层各管什么。

  1. 01

    能力层 · MCP 服务器

    把系统能力工具化：search_assets 检索、get_asset_metadata 元数据、aggregate_uploads 统计、export_to_excel 导出、list_collections 专辑。权限受控，任意兼容 MCP 的智能体都以同一方式调用。

    不再为每个平台写一套集成：同一接口支持 stdio 与 SSE 两种传输。

  2. 02

    编排层 · Agent Skill

    封装高频任务流程，解决「什么时候调、按什么顺序调」。时间范围解析、多次工具调用、结果格式化与文件命名由 Skill 串成固定流程，用户只说一句话。

    例「生成季度上传报告」：解析 2026-Q3 → 调 aggregate_uploads（按上传者）→ 出表 → 命名导出。

  3. 03

    接入层 · Agent Plugin

    把上面两层打包成智能体客户端里可安装的插件：装上、登录一次就能用。首期适配腾讯 WorkBuddy（内置 MCP 与 Skills 扩展机制），后续 Codex、Claude Code、OpenClaw 复用同一服务器。

    换智能体只换这一层：工具与 Skill 不用重写。

一句话记住：能力决定「能调什么」，编排决定「怎么组合」，接入决定「装到哪里」——换智能体只换最上面一层，下面两层不动。

这套演示想确认的三件事

01

工具边界

智能体只能调用光圈AI 开放的 MCP 工具：检索、元数据、上传统计、导出、销售链接。没有「随便改素材」，权限仍然由光圈AI 决定。

02

参数可见

每次调用都展示工具名、入参与耗时，客户和内部审核都能看懂智能体到底做了什么。

03

可回溯

所有调用写入审计日志，能追溯到人、素材、链接和导出的文件，满足对外授权留痕要求。

演示数据均为示意；真实上线后工具返回结构不变，仅数据来源替换为生产库。
